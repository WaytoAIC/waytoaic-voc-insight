# 打标表的格子

打标的结果是一张宽表 `tagged.csv`：清洗脚本出的 `cleaned.csv` 原样保留，后面接上打标的格子。
**格子的名字是固定的**，脚本认这些名字。三条线尽量共用同一套。

## 通用写法

- 一个格子里有多个值：用**分号加一个空格**隔开 —— `整体高度:偏高; 选档指引`
- 两头都可能错的细项要带方向：`名称:方向` —— `整体高度:偏高`。方向只能用标签表里给这个细项声明的那两个
- **没内容就留空**。不要写"无""NA""没有"——会被当成一个标签统计进去
- 标签名必须跟标签表一字不差。脚本会校验，不在表里的直接报错
- 夸的片段记在"过程感受"里时加 `(夸)`：`佩戴舒适度(夸)`

## 退货线

| 格子 | 填什么 | 单个 / 多个 |
|---|---|---|
| `哪件事_大类` | 这条原话主要在说哪一大类 | 单个 |
| `哪件事_细项` | 具体说到哪几件事（可带方向） | 多个 |
| `谁在说` | 自己用还是替人买；上一个办法；之后打算怎么办…… | 多个 |
| `什么情况下` | 在哪、什么时候、跟什么一起用 | 多个 |
| `过程感受` | 舒不舒服、体不体面、安不安心……；夸的加 `(夸)` | 多个 |
| `该谁改` | 配置里那六个之一 | 单个 |
| `多严重` | 严重 / 中度 / 轻度 | 单个 |
| `能否挽回` | 是 / 否。原话里出现已经换了、打算换的，填"是" | 单个 |

## 评论线

| 格子 | 填什么 | 单个 / 多个 |
|---|---|---|
| `好评的事` | 夸到了哪几件事（**不带方向**） | 多个 |
| `差评的事` | 骂到了哪几件事（可带方向） | 多个 |
| `落差指向` | 客户说"跟页面说的不一样"时，具体指的是哪件事；指不出来填 `没指明` | 多个 |
| `谁在说` / `什么情况下` / `过程感受` | 同退货线 | 多个 |
| `再问一层` | `细项>问什么=答案`，问什么、有哪些答案在配置里定 | 多个 |
| `该谁改` / `多严重` | **只在"差评的事"不为空时填**，否则留空 | 单个 |
| `整体好坏` | 好评 / 中性 / 差评。**以文字为准，不跟星级走** | 单个 |

一条评论又夸又骂是最常见的情况（"戴着舒服，但是放不回充电盒"）。两边都要记，丢掉它就丢掉了最值钱的信息。

## 容易错的几处

| 情况 | 怎么填 |
|---|---|
| 客户只写了一个词（"fit""case"） | 细项填带"(没说方向)""(没说清)"的那一项；该谁改填"说不清" |
| 客户说"跟描述不符"但没说哪里 | 评论：`落差指向=没指明`；退货：细项填"与预期(泛指)" |
| 同一条原话里两个方向都有（"腰大、腿小"） | 两个都记。这不是矛盾，是比例问题，比单向更有价值 |
| 退货原话里有夸的片段（"东西不错，但是……"） | 记在"过程感受"里加 `(夸)`。**不许拿它算满意度**。它的用处是告诉你哪些卖点连退货的人都认 |
| 转述别人的感受（"买给我爸，他说不舒服"） | "谁在说"标替谁买；该谁改要谨慎，转述往往丢了具体原因，多半是"说不清" |
| 原话编码坏了（一串问号） | 意思还能认就照常打；认不出来就不打，并在"这批数据答不了什么"里写明 |
