# 两张表，和复盘

飞书多维表格里只建两张表。脚本算数要用的全量明细留在本地文件里——**本机的是准的，飞书是给人看的**。

```bash
python scripts/export_tables.py work/tagged.csv work/insights.json --source 退货 --outdir outputs/两张表
```

## 表一 · 原话 + 打标

一行一条客户原话。三条线（退货 / 评论 / Reddit）存在同一张表里，用"来源"这一格区分。**同表存，不混算。**

| 格子 | 说明 |
|---|---|
| 编号 | `退-012` `评-045` |
| 来源 | 退货 / 评论 / Reddit |
| 产品 | |
| 原话 | 客户怎么说的，一字不改 |
| 中文意思 | |
| 谁在说 / 什么情况下 | |
| 说的哪件事 | 评论里会标 `好·` `差·` |
| 好还是不好 | 退货恒为差评 |
| 该谁改 / 多严重 / 能不能挽回 | |
| **用在哪条行动上** | 连到表二 |

## 表二 · 行动

一行一条行动。**前面的格子 AI 填，后面四格人填。**

| 格子 | 谁填 |
|---|---|
| 行动编号、产品、问题、动作、哪个部门、哪一档、怎么才算做完、**依据的原话**（连到表一） | AI |
| **责任人、验证日期、状态、复盘结论** | 人 |

"怎么才算做完"这一格按五样写全：看哪个数 · 现在多少 · 要到多少 · 哪天看 · 要是没变说明什么。

两张表靠"依据的原话 ↔ 用在哪条行动上"连起来：点开一条行动，能看到它是凭哪几条原话提的。
"每个结论都要有原话"这条规矩，就落在这一格上。

## 在飞书里建表时，两件事不能错

1. **"验证日期"必须建成日期格，不能建成文字格。** 文字格里人会填"9 月中旬""页面更新后 2 周"——人看得懂，
   飞书看不懂，到期提醒发不出来，复盘就只能靠记性。常见的下场：一张几十条行动的表，"怎么才算做完"全填了，
   复盘结论几乎全空——不是人不想复盘，是没有东西催
2. **开一条飞书自带的到期提醒**（验证日期当天提醒责任人）。不需要 AI，这是最便宜的一步

## AI 管到哪，人管到哪

| | 谁 |
|---|---|
| 把结论写成一条条行动、建好表、填好前面的格子 | AI |
| 认领（责任人）、定验证日期 | 人 |
| 去做、改状态 | 人 |
| 到日子，回来读"看哪个数"里写的那个数 | 人 |
| 写复盘结论：变了没有；没变的话，按"要是没变说明什么"转向 | 人 |

AI 不改状态，不催人，不替人下复盘结论。顶多在人要的时候，把前后两个数摆在一起。

## 复盘之后，留下什么

一轮跑完，四样东西要留下来，下一轮开工先读：

| 从哪来 | 留下什么 | 下一轮怎么用 |
|---|---|---|
| 采集 | **原话库**（表一）：客户怎么说的，一字不改，个人信息去掉 | 写页面、写广告、写内容时直接用客户的说法 |
| 分析 | **标签表 + 判例**：怎么归类；拿不准的那几条当时是怎么定的 | 下一轮照这个贴标签，前后两轮的数才能比 |
| 行动 | **动作库**（表二）：什么问题配什么动作、怎么才算做完 | 同类问题再出现，不用从头想 |
| 复盘 | **验证过的经验**（表二的复盘结论）：哪些动作真让数字变了，哪些做了也白做 | 下次排优先级，先做验证过有用的 |
